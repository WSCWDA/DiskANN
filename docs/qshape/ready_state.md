# P3.1-A: bounded READY state
Opt-in retention=bounded, sharing=inflight, one L per process, diagnostics off.
Successful publication retains the existing payload until quiescent file close/open or coordinator destruction. Full budget rejects new admissions; no TTL/LRU yet. READY hits are a subset of shared_hits, not additional hits. In-flight hits = shared_hits - ready_hits. Live payload cap = inflight budget + READY budget; active in-flight reservations and retained map bytes have separate caps. Evicted pinned payload remains charged to live bytes. Metadata excluded. Peak live/inflight samples may underestimate instantaneous peaks due to concurrent release; atomic reservations enforce caps independently. No background eviction. First-fill retention is intentionally not a performance policy. Cache-only and diagnostics integration deferred. File lifecycle must be quiescent.
Run test_ready_retention.cpp with g++ -std=c++14 -O2 -pthread -Iinclude. Run run_ready.sh with standard run_sharing environment and fresh OUT; validate_ready.py checks result hashes, accounting and sampled peaks. No speedup requirement for A.
