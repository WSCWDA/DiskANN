# P1.2 scheduler
The group-aware scheduler uses a mutex-protected pending-group window and prefers the group with most running queries, ties by original group order. No query waits for a group to finish. The lookahead is a pending-group search bound, NOT a hard active-group cap. With equal group size and workers, or when all groups are initially inactive, it can behave exactly like FIFO; indeed this first policy may be equivalent to FIFO for contiguous groups. Treat it as a falsifiable baseline, not a guaranteed improvement. No I/O sharing. Original query IDs and per-query search semantics remain unchanged. Grouping breakdown covers distance, ranking and maintenance within the grouping loop; residual includes setup. Worker scheduler cost includes mutex contention and completion, excludes terminal failed take and OpenMP internal dispatch. Worker busy fraction is search-scope time divided by configured workers times search wall time, not CPU utilization. Trace overlap uses observed submit/harvest intervals, not physical device service. Validator checks exact IDs/distances, recall, per-query counters, permutation, timestamps, trace pairing and reports descriptive comparisons. Run with fresh OUT, same inputs as P1.1. Unit test: g++ -std=c++14 -pthread -Iinclude tests/qshape/test_query_scheduler.cpp -o /tmp/qshape_scheduler_test && /tmp/qshape_scheduler_test. Benchmark: bash scripts/qshape/run_scheduler.sh. Validation: python3 scripts/qshape/validate_scheduler.py --out "$OUT" --groups 64 128 256 --threads 64. Trace storage scales with runs; start with one group and one repeat. Python validator holds one trace's intervals in memory. Use python without -O. Target compilation and experiment validation pending. No P2/P3.
