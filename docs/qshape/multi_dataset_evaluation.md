# P4.0-A multi-dataset evaluation
Production frozen; independent Python runner reuses run_sharing.sh and final factorial query checks. One config/output per dataset and search parameter set. Explicit data type (not inferable from byte width), L2 only, static full-vector indexes, GT IDs+distances. Audit validates structural metadata and hashes, not semantic correctness of GT or vector contents. Optional base file; PQ pivots existence only. Multi-sector layout parsed, runtime support requires smoke. No disk PQ, reorder or frozen points. Device counters are Linux block-layer counts, not NVMe commands; isolate device and record mount mapping manually. Full input hashes may take substantial time. Recall floor in percent must be chosen after A0 calibration. Exact result hashes and per-query logical work must match within a configuration. No cross-dataset equality requirement. Run unit tests then audit, A0 calibration, ten-policy smoke, three-repeat formal only after smoke. No production changes. Example config:
```json
{"binary":"/path/search_disk_index","index_prefix":"/path/index","query":"/path/query.fbin","gt":"/path/gt","data_type":"float","dist_fn":"l2","threads":64,"beam":64,"l":100,"k":10,"ready_mib":16,"min_recall":95,"repeats":1,"policies":["A0"],"device":""}
```
Commands: python3 scripts/qshape/test_multi_dataset.py -v; python3 scripts/qshape/multi_dataset_eval.py audit --config CONFIG; python3 scripts/qshape/multi_dataset_eval.py run --config CONFIG --out OUT; python3 scripts/qshape/multi_dataset_eval.py validate --out OUT. Use fresh directories for changed configs. No automatic dataset download/build or cross-dataset aggregation in this stage.
