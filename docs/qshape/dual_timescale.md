# B2.1-A offline feasibility
Replay D0/D2 from three validated A2 traces, all logical accesses sorted by timestamp/query/sequence. Instantaneous fill, no in-flight sharing or real SSD. R0 sharded LRU; R1 production-compatible CMS hash and strict admission; R2-R5 window LRU with evicted candidate competing against main LRU; R6/R7 direct-mapped last-touch ghost (1024 uint64 tags per shard, 512 KiB), first-touch misses compete directly for main, subsequent ghost matches enter window on miss. Ghost has no TTL and is not exact second-touch history. Fixed 64 shards, 16 MiB logical payload, no duplicate residency. Window eviction counts include promotion, unused counts refer to window residency, not final release. Python model stores keys not payload; metadata bytes are counter/tag payload only, not Python RSS. Hash memoization is offline acceleration, not deployable metadata. Replay throughput is Python diagnostic only. Run test_dual_timescale.py; run_dual_timescale.py run --source A2 --out smoke --repeats 1 --limit 100000; formal --repeats 3 with no limit; validate --out formal. Suggested gate: similarity mean miss reduction >=3%, all three positive, original no material regression, inspect churn. No production changes. R1 equivalence to existing C++ replay needs cross-check on identical stream before interpreting candidate gains.
